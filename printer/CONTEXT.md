# Printer 项目术语表

## 核心术语

| 术语 | 定义 |
| --- | --- |
| 打印指令 | 外部系统提交的业务数据和模板参数，表示希望打印什么内容。 |
| 打印任务（PrintJob） | 服务端持久化的一次打印请求，具有唯一 ID、幂等键和完整状态历史。 |
| 打印模板 | 把业务数据转换为打印内容的版本化规则。 |
| 渲染产物（Artifact） | 根据模板生成的设备文件或预览文件。设备产物优先使用 ESC/POS 字节流。 |
| 设备（Device） | 运行 ESP8266 固件并主动建立到 VPS 的 TLS TCP 控制连接，接收打印任务并按授权代理访问内网 TCP 服务。当前代码仍通过 HTTPS 轮询作为打印恢复通道。 |
| 打印机（Printer） | 连接在设备上的实际打印硬件。一个设备可以报告一个或多个打印机能力。 |
| 投递尝试（DeliveryAttempt） | 服务端把某个任务租给设备，并等待设备执行结果的一次完整尝试。 |
| 租约（Lease） | 服务端暂时授予某设备处理某任务的时间窗口，过期后任务可重新排队。 |
| 反向 TCP 隧道 | ESP8266 主动建立到 VPS 的 TLS TCP 长连接，承载打印任务、设备心跳、打印结果和受控的内网 TCP 代理流；首版每台设备只允许一个活动代理流。 |
| 打印机发现 | VPS/Web 枚举已配置内网 CIDR 和预设端口，通过 8266 对单个地址执行 TCP/只读协议探测；8266 不负责扫描网段。 |
| 轮询 | 隧道不可用时，ESP8266 主动请求服务端查询是否有可处理打印任务的恢复通信方式；不承载持续代理流。 |
| 打印完成 | 首版定义为设备已向打印机发送完整数据且打印机接口未报告错误；真实出纸确认需要打印机提供反馈能力。 |

## 状态语言

- `accepted`：指令已经持久化。
- `rendering`：渲染 Worker 正在生成产物。
- `queued`：设备产物已准备好，等待设备领取。
- `leased`：设备已领取任务，尚未确认开始或完成。
- `printing`：设备正在向打印机发送数据。
- `succeeded`：设备确认本次打印成功。
- `render_failed`：服务端渲染失败。
- `failed`：设备或打印机执行失败。
- `expired`：设备租约超时。
- `cancelled`：尚未执行的任务被取消。
